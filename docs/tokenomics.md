## Disclosure rules

1. **One source of truth.** The website and this table read from the same facts. A value is not quoted anywhere until it is stated here.
2. **Address first.** The contract address is announced before any distribution detail is discussed, so that every later claim can be checked against the deployed code.
3. **Show the whole address.** The full address is always displayed, never shortened with an ellipsis, so that a copy-paste can be compared character by character.
4. **No date without a date.** If a launch time is not fixed, none is shown.
5. **Changes are dated and explained.** Any change to a published parameter is recorded in the history of this file with the reason.

## What a complete disclosure will contain

- Supply and whether it can ever change, with the on-chain function or absence of one that proves it.
- Every allocation as an absolute amount and a percentage, with the receiving address.
- For each locked or vesting allocation: start, cliff, end, and the contract that enforces it.
- Where initial liquidity sits and who controls the pool position.
- Any fee taken by the protocol, how it is calculated, and where it is sent.
- Any privileged role in the contracts, who holds it, and how it can be revoked.

## What this document does not do

It does not forecast price, promise returns, or suggest that holding the token confers any right. It is a description of how facts will be published, not an offering.
